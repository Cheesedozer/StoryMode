## YOUR TASK

Design the foundation every later phase builds on. The protagonist is the player's persona (see PERSONA DATA, if provided); everything here should create pressure on them.

Return a JSON object with these fields:

### 1. core_premise (string)
One to five sentences that pass the goal–motivation–conflict test: the protagonist (by role), the catalyst that starts the story, what they want, why they want it, and who or what stands in their way. Use the room to make it specific to this story rather than compressing it into a slogan. Leave the outcome open.

### 2. blueprint_title (string, optional)
A short, specific title.

### 3. setting (object)
```json
{
  "location": "where the story happens, specific enough to picture",
  "time_period": "when it happens",
  "atmosphere": "mood, sensory texture, and the pressures the place itself puts on people"
}
```

### 4. antagonistic_forces (object)
Whatever pushes back against what the protagonist wants. In quiet or kishōtenketsu stories it can be small or internal: time, habit, a fear.
```json
{
  "description": "who or what opposes the protagonist, and what they control",
  "nature": "external | internal | environmental | mixed",
  "motivation": "what the opposition wants and why; it should be understandable from its own point of view",
  "manifestations": ["3-5 concrete ways the opposition acts on the protagonist during the story"]
}
```

### 5. arcs (array)
One entry per arc listed in STORY ARCS, in the same order, keeping each arc's `id`, `role` and `shape`:
```json
[
  {
    "id": "spine",
    "role": "spine",
    "shape": "the shape id given above",
    "question": "the question this arc asks, specific to this story and open (for example 'Can they get the ledger out of the vault?')",
    "stage_notes": { "<stage id>": "one sentence on how this stage plays out in this story" }
  }
]
```
Give every stage of every arc a note. Threads should touch the spine: a romance between two members of the crew, a mystery about who opened the gate.

### 6. arc_structure (object)
A summary of the spine in four lines:
```json
{
  "opening_hook": "the catalyst: what happens that the protagonist cannot ignore",
  "escalation_pattern": "how pressure, inquiry, or closeness builds through the middle, as the spine's shape does it",
  "climax_nature": "the situation at the spine's climax stage: who is there, what is at stake or at issue (not how it turns out)",
  "resolution_style": "the emotional register of the ending, which can hold for several different outcomes"
}
```

### 7. content_boundaries (object)
The intensity this story intends, within whatever the user's content settings allow (they decide how explicit anything can be; these fields describe the story's own intent):
```json
{
  "violence_level": "none | mild | moderate | intense",
  "romance_level": "none | mild | moderate | explicit"
}
```

### 8. tone_and_style (object)
```json
{
  "primary_tone": "overall mood, drawn from the story type, scenario, and writing style",
  "narrative_voice": "point of view and narrative distance",
  "pacing": "how the story moves",
  "key_stylistic_elements": ["3-5 concrete writing techniques"]
}
```

## RESPONSE FORMAT

Return a single JSON object with the fields above and nothing else.
